same PR as the task that hit it. Never edit `design.md` in a feature PR.

| 2026-10-23 | T08 | `Raw<'a>` in design §7.3 carries `&Type`, but `FromSql` gives `ty` a lifetime unrelated to `'a`. | `Raw<'a>(Option<&'a [u8]>)`; the type comes from `row.columns()[i].type_()`. | 2026-10-24 | T22 | Design §7.6 says the guard's drop starts settling, but pyo3-async-runtimes drops the Rust future on another thread after asyncio cancels the Python future, so `cancel(); await next()` could still see `Busy`. | Settling also starts from a done callback on the Python future (`exec::watch`), which asyncio runs before the awaiting task resumes. | 2026-10-24 | T22 | The backend key data is private in tokio-postgres, and `cancel_query` does not wait for the server to close the socket. | `CancelTarget` opens its own TCP or Unix socket, calls `CancelToken::cancel_query_raw` on `&mut` stream, then reads to EOF. | 2026-10-24 | T22 | The acceptance asks for a test-only counter of CancelRequests. | `rowx_pg::cancel::requests_sent()` is exposed as `rowx._core._cancel_requests_sent()` (underscore-prefixed, in `_core.pyi`). | Needed to assert that a plain SQL error sends none. |
| 2026-10-24 | T22 | Wiring edits outside the task's Files list. | `rowx-pg` `lib.rs`, `conn.rs` (stores the `CancelTarget`) and tokio `net`/`io-util` features; `rowx-py` `conn.rs`/`exec.rs` run operations through `cancel::spawn`; `close()` sends a cancel when busy. | The operation must run as its own task, owned by the cancel module. |
