# Why rowx

rowx is SQLx for Python: typesafe raw SQL as a [PEP 750](https://peps.python.org/pep-0750/) t-string, checked by
`rowx check` against a live Postgres 18 database, with no ORM. The [user guide](guide.md) is how to write and run a
query. The [packages](packages.md) page lists the three distributions.

## Comparison

The rowx row follows the guide and reference. Each other row links to that project's documentation.

| | Where the SQL lives | Whether a live database checks it | ORM or not | Whether the project is a Postgres driver | Offline cache versus generated code |
|---|---|---|---|---|---|
| rowx | An inline t-string on `query[T]` ([Queries](guide/query.md)). | Yes. `rowx check` prepares and describes every query against a live Postgres 18 database and never imports or executes application code ([checker guide](guide/checker.md), [user guide](guide.md)). | No. Raw SQL in t-strings ([user guide](guide.md)). | Yes. `rowx-postgres`, on tokio-postgres ([packages](packages.md), [driver](reference/driver.md)). | Described column metadata is not written to a disk cache ([checker reference](reference/checker.md)). |
| [SQLx](https://docs.rs/sqlx/latest/sqlx/) | SQL string literals in the [`query!`](https://docs.rs/sqlx/latest/sqlx/macro.query.html) macro. The repository is [transact-rs/sqlx](https://github.com/transact-rs/sqlx). | Yes, at compile time. `DATABASE_URL` must point at a database server with the schema the query string is checked against, unless [offline mode](https://docs.rs/sqlx/latest/sqlx/macro.query.html#offline-mode) is used. | SQL toolkit for Rust. The crate docs describe compile-time checked queries without a DSL. | Yes. [`Postgres`](https://docs.rs/sqlx/latest/sqlx/struct.Postgres.html) is a PostgreSQL database driver. | [Offline mode](https://docs.rs/sqlx/latest/sqlx/macro.query.html#offline-mode) stores a `.sqlx` directory so a later compile can skip the live database. |
| [asyncpg](https://magicstack.github.io/asyncpg/current/index.html) | SQL strings passed to connection methods such as `execute` and `fetchrow` ([usage](https://magicstack.github.io/asyncpg/current/usage.html)). | The usage guide shows those methods running the SQL on a connection. | A PostgreSQL protocol library for Python and asyncio. The [FAQ](https://magicstack.github.io/asyncpg/current/faq.html) describes using it with the SQLAlchemy ORM. | Yes. The introduction describes an implementation of the PostgreSQL server binary protocol. | The introduction and usage guide describe a runtime library. |
| [psycopg](https://www.psycopg.org/psycopg3/docs/) | SQL strings passed to `execute` ([basic usage](https://www.psycopg.org/psycopg3/docs/basic/usage.html)). | The usage guide shows `execute` sending the SQL. [Static typing](https://www.psycopg.org/psycopg3/docs/advanced/typing.html) annotates the Python API and the rows that come back. | PostgreSQL database adapter for Python. | Yes. The documentation describes a PostgreSQL database adapter for Python. | The usage guide describes a runtime adapter. |
| [SQLAlchemy](https://docs.sqlalchemy.org/en/21/intro.html) | SQL expression objects, and an ORM mapped onto a schema ([overview](https://docs.sqlalchemy.org/en/21/intro.html)). | The overview executes those expressions through a DBAPI. | Yes. SQL toolkit and object relational mapper. | A dialect over a DBAPI. It is designed to operate with a DBAPI ([Installing a Database API](https://docs.sqlalchemy.org/en/21/intro.html#installing-a-database-api)). PostgreSQL options include psycopg and asyncpg ([dialect](https://docs.sqlalchemy.org/en/21/dialects/postgresql.html#dialect-postgresql)). | The overview describes a runtime toolkit. |
| [sqlc](https://docs.sqlc.dev/en/latest/) | Schema and queries live in separate SQL files ([generate](https://docs.sqlc.dev/en/latest/howto/generate.html)). | `sqlc generate` parses the SQL files and analyzes them with a built-in engine. A database connection is optional, for enhanced analysis ([generate](https://docs.sqlc.dev/en/latest/howto/generate.html)). | Generates code from SQL. | The PostgreSQL tutorial emits code that runs with a separate driver, `pgx` ([tutorial](https://docs.sqlc.dev/en/latest/tutorials/getting-started-postgresql.html)). | `sqlc generate` emits the host code the application calls. With managed databases, analysis can also be cached locally ([generate](https://docs.sqlc.dev/en/latest/howto/generate.html)). |
