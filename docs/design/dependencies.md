# Dependency evaluation

| Candidate | Use | Verdict |
|---|---|---|
| **sqlx** as the runtime driver | Connections, codecs | **No.** Parameters are binary-only, so every Python type and Postgres type pair needs a hand-written encoder, and `int`→`numeric` and `str`→`date` failed. Its `&mut` connection serialises everything. It has no public cancel API: a cancelled `pg_sleep(3)` kept running. It pulls in 180 crates and builds in 19 s, against 90 crates and 13 s. |
| **sqlx** `describe` | Nullability | **No.** It is `#[doc(hidden)]`, `offline`-gated and only reachable through `macros`, and its signature changed in 0.9. It gives unsafe answers ([Evidence: why not sqlx's describe](nullability.md#evidence-why-not-sqlxs-describe)). rowx copies its *model* and ports its test cases with attribution; sqlx is MIT/Apache-2.0. |
| **tokio-postgres** | Runtime and describe | **Yes.** It has a public describe API (`Statement::params/columns`, `Column::table_oid/column_id`), raw `FromSql`, a per-parameter `encode_format`, `Kind` resolution and cancel tokens, and it can pipeline later. psqlpy shows the stack works in production. |
| **deadpool-postgres** | Pool | **No.** Its statement cache conflicts with rowx's cache and its cancel/settle path. `deadpool::managed` (without `-postgres`) was also rejected by the pool spike (#75): it works with about 100 lines of layering, but rowx's own pool is smaller, faster and adds no dependency (decision log C25). |
| **datafusion-sqlparser-rs** | Client-side parsing | **Not in v1.** The server already provides validity, types, parameter inference and outer-join nullability, and t-strings give placeholder positions. A parser would add dialect gaps, so queries that Postgres accepts would need a fallback path. **Revisit for:** (a) NOT NULL narrowing of computed columns beyond the [whitelist](nullability.md#computed-columns) (`WHERE x IS NOT NULL`, arithmetic over proven values), building on sqlty's `nullability.rs` (MIT); (b) detecting the statement kind before connecting; (c) finer positional mapping across scan boundaries ([Plan walk](nullability.md#plan-walk-explainrs-a-pure-function-over-serde_jsonvalue)). |
| **sqlty** | Reference | MIT, borrowed with attribution: `_params.py` rules, `_config.py` ergonomics and the fixture style. Not a dependency. |
| **ruff_python_parser** | A checker in Rust | **No.** Its API is unstable, and stdlib `ast`/`tokenize` are exact for 3.14. |
| **sha2** | Migration checksums | **Yes.** Migration checksums are SHA-384 over the raw file bytes, to match sqlx byte for byte. `sha2` is the RustCrypto implementation: pure Rust, MIT/Apache-2.0, no system library, and sqlx uses it for the same job. |
| **crc32fast** (or `crc`) | Migration lock key | **Yes.** The advisory-lock key is sqlx's `0x3d32ad9e * crc32(current_database())`, so a sqlx migrator and a rowx migrator exclude each other. Only the standard CRC-32 (IEEE) is needed; `crc32fast` is small and widely used, and `crc` is an acceptable substitute if it is already in the tree. Hand-rolling a table was rejected, because a wrong key would silently break the sqlx exclusion. |
